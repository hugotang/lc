# Experimental tap sync

Open two or more containers of the same app in virtual windows and place them side by side. In the Dock's layout menu (or Multitasking settings), open **Tap Sync (Experimental)**. Choose the source and select its followers, align all app screens, then start. The floating status button pauses forwarding immediately; tap it again while paused to open setup. Clearing the group removes the status button.

Only completed, direct, single-finger taps lasting at most 350 ms and moving at most 10 guest points are eligible. Window bars, grid dividers and host controls are outside the guest capture path. Coordinates are relative to the guest window, independent of the host's reserved margins. Followers must have the same interface orientation and an aspect ratio within 2.5%; content scales can differ, although matching sizes/scales help prevent app layout differences. Swipes, long presses, multiple fingers and keyboard input are not replayed.

Tap sync reproduces input, not app state. Loading screens, dialogs, animations and account-specific screens can diverge. Delivery is sequential and asynchronous, not frame-locked. The count reports completed delivery to all selected guest input pipelines, not confirmation that the apps performed the intended action. Game and SwiftUI compatibility needs device testing.

Changing geometry, minimizing/closing windows, PiP, leaving the foreground, keyboard input or directly touching a follower pauses the session. A lost connection, unsupported replay API, expired command or slow follower also stops forwarding. Align the app screens before resuming. A workspace saves only the source/target container identifiers; restoring, duplicating or editing the saved layout never enables input forwarding. Invalid saved groups are discarded without losing the layout.

## Implementation and validation

- Each virtual LiveProcess launch receives its own anonymous NSXPC listener endpoint. The host binds it to the launched process identifier, and each connection represents one container; packets cannot select a different source by supplying an identifier.
- The guest observes `UIApplication.sendEvent:` only for this feature's selected session. A completed tap carries normalized coordinates, guest dimensions/orientation, tap count, duration and monotonic timestamp. Inactive sessions return immediately; there is no polling timer, screenshot processing or input saved to disk.
- Followers construct a guest-local `UITouch` and a separate `UITouchesEvent`, with digitizer metadata, and deliver began/ended phases through their own `UIApplication`. The system's current physical-touch event is never cleared or reused. No global event-dispatch service or new entitlement is used. Private selectors and HID construction functions are checked before enabling replay; missing APIs and Objective-C exceptions disable it.
- Every start has a fresh session ID. Both ends check ordering and reject stale sessions; the queue holds at most four pending taps, commands expire after 750 ms, and replies have bounded timeouts. The source is prepared after the followers. Pause invalidates queued work and cancels any injected contact; late replies cannot reactivate a stopped session. A short asynchronous hold lets rendering loops observe the down/up phases.
- Automated tests cover coordinates, invalid numbers, orientation/aspect changes, tap bounds, source identity, sequence gaps, duplicates, queue limits, expiry, stopped sessions and workspace serialization/preservation. CI also compiles and packages the host and guest client. These checks do not establish physical-device replay compatibility, input latency or power consumption.

Private API references used to check the design and ABI: [KIF's touch construction](https://github.com/kif-framework/KIF/blob/master/Sources/KIF/Additions/UITouch-KIFAdditions.m) and [event construction](https://github.com/kif-framework/KIF/blob/master/Sources/KIF/Additions/UIView-KIFAdditions.m) (Apache-2.0); [WebKit's IOKit SPI declarations](https://github.com/WebKit/WebKit/blob/d142da35a21447b2820804ffa12435fde6678f5b/Source/WebCore/PAL/pal/spi/ios/IOKitSPIIOS.h). See the device checklist in `Tests/MultitaskManualChecks.md` before treating this as a stable feature.
