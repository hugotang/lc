# Upstream sync — 3.8.46

Integrates `LiveContainer/LiveContainer` main through `b0f53e8`, checked on 2026-11-23. This adds seven upstream commits after the 3.8.45 integration at `b7cfda60c39933a94d616f2a358ac2e48fd4e5cd`. The merge retains the fork's helper v2 integration and custom window, location, audio, workspace and input-sync behavior.

The fork keeps its GitHub-hosted macOS/Xcode 26.2 build configuration and its existing checks. All multitasking sources, including the fork's Dock, input-sync, performance and workspace additions, now live under `LiveContainerSwiftUI/MultitaskSupport`. Project membership, relative imports, CLI tests and generated simulator projects use the new location. The shared framework retains Swift 5 mode and the location bridging header. Both the main app and LiveProcess declare `MusicHapticsSupported`. Version 3.8.46 follows the fork's installed 3.8.45.

OpenSSL is downloaded from release 3.6.5000 rather than cloned as a submodule. `.github/prepare_dependencies.sh` pins the archive SHA-256, fails on download/checksum/extraction errors, and stages extraction before installing `Dependencies/OpenSSL.xcframework`. A receipt outside the signed framework allows repeat preparation; an existing unrecognized framework is left intact. Obsolete OpenSSL project references and search paths are removed.

The upstream fixes also cover missing team-ID entitlements, the system Liquid Glass check, debug entry points and removal of SideStore components from extra LiveContainer copies. Data and tweak directory enumeration runs in a detached utility task, with published model updates on the main actor. The new LINKEDIT string-pool alignment detection applies to both app and helper executables. Main patch revision 8 and helper patch revision 2 make installed guests run the new detection on their next preparation; successful helper bundle signing remains tracked independently.

Sources now load saved entries and refresh only when the Sources tab is first opened. Adding a source also ensures saved entries are loaded before persisting changes, including when a source deep link arrives before the tab appears. Subsequent tab visits reuse the loaded model. The fork's download-size display remains available.

Custom location, compact joystick, live shortcut switching, fixed aspect ratios, audio options, workspaces, Dock and touch-only Input Sync remain present. Replacing an installed guest snapshots its ratio/audio/location preferences before removing the old bundle and restores those values before constructing the replacement settings model. Location revision, favorites and shortcut preference stay together; absent choices remain absent, and signing/patch metadata comes from the incoming bundle. `LCAppModel.copy` retains the other installation settings, including Helper Process Support.

Helper v2 uses PlugInKit discovery and process launch together with a host bootstrap service to provide launch configuration and connect the guest's extension subsystem. It replaces the earlier custom `NSExtensionContext` wrapper and its auxiliary-listener handshake. Shared preference suites continue to use the parent guest's container; a helper's own standard defaults remain in its extension subcontainer. A parent-container security-scoped bookmark provides access to shared preferences.

Guest helper launches carry an explicit environment marker, so an existing helper service does not reroute ordinary windows or SideStore. The child consumes the marker before entering the guest. Bootstrap and configuration retrieval share a 30-second deadline. Host launch registration, PID matching and completion run on one serial queue; failures, disconnected peers and timed-out launches are removed. Preparation errors are returned before asking PluginKit to launch.

The fork retains helper patch/signing recovery: preparing extensions is opt-in, patch and signing revisions are separate, and interrupted signing remains pending until the bundle signs successfully. Replacing an app must not carry the old bundle's patch or signing metadata into the incoming version.

`GuestPlugInHostTests.m` and `GuestPlugInClientTests.m` exercise the production host/client code with anonymous XPC connections and fixtures for system launch/bootstrap services. They cover PID authentication, configuration delivery, both request/PID arrival orders, parent bookmark preparation, ordinary/helper launch routing, failed launches, cleanup and bounded waits. The platform bootstrap registration and native guest extension remain device-only checks.

Validation must include the Release archive and both IPA variants, helper v2 launch/bootstrap checks, preference routing and signing recovery, replacement-setting persistence, and the existing window/input/Dock/location suites. The previous v1 tests and device results do not establish v2 compatibility. Device checks must verify actual JIT helpers or RAM donors, both sides of extension communication, cancellation and failed launch, parent/helper preference updates, source deep links, and existing multi-account game flows.
