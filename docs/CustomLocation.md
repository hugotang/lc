# Custom Location (3.8.38)

Open an app's Settings → **Custom Location**. This is a built-in option: the settings UI uses MapKit and the guest bootstrap installs the location module from LiveContainerShared before loading guest initializers. No separate dylib installation is required.

The setting is off by default. Turn it on to select a location, or choose a location first and enable it later. Search for an address or place, select a result, long-press the map, drag its pin, select the map center, or enter decimal latitude/longitude. Search results never select themselves. **Use This Location** commits the selection; Cancel preserves the saved value. Address search and map imagery need a network connection; coordinate entry does not. The picker does not request device location permission or display the user's real location. Its blue **Current Location** marker is the custom point currently supplied to the app; when simulation is off, it is labeled **Saved Location**. The orange **Selected Location** marker is the draft. Editing or dragging the draft never moves the baseline. Return to Current/Saved Location changes only the camera. Coincident points share one marker with both role labels; moving the draft reveals the fixed baseline.

Coordinates use WGS 84 decimal degrees, latitude first (−90…90) and longitude second (−180…180). Negative values represent south/west. Decimal commas are accepted in the separate numeric fields. Empty, nonnumeric, nonfinite and out-of-range values cannot be saved; `(0, 0)` is a valid deliberate selection. The saved point includes a short optional place name. Search queries/results are not persisted.

One position is stored per app in `LCAppInfo.plist`, shared by its accounts. Changes now apply immediately to running accounts, including managers created while simulation was disabled. Disabling retains the point and resumes the app's requested system location services. Ordinary launches, virtual multitasking and native LiveProcess windows use the same bootstrap gate. TweakLoader injection must be enabled. SideStore and 32-bit translated apps are excluded; the host's settings map never installs the guest hook.

## Live controls

Open Location from a virtual window's title menu or Dock, or use **Open Location Controls** in app settings. The optional movable shortcut defaults off. Its switch applies immediately in settings and to running ordinary/native/virtual windows. Turning it off hides that app's floating controls and stops movement; manually opened controls leave no shortcut after collapse while it is off. Virtual windows also retain their title and Dock menu entry. Re-enabling shows the shortcut without a relaunch. A scene only shows one app's location controls at a time. The panel shows the app name, shared-account scope, current point and simulation/movement status. Switching apps replaces the scene's previous location panel. Save up to 20 places and select or remove them from Favorites.

Choose Joystick to replace the settings panel with a separate **184 × 228 point** floating control. It contains a 140-point stick, a speed menu, Stop, Settings and Collapse. Drag the dedicated handle to reposition it without moving the location. Coordinates, favorites, map selection and system-location restoration stay in the settings panel; touches outside the floating control continue to the app. Choose Settings to return to those options.

Use the joystick to move north-up at walking (1.4 m/s), running (3 m/s) or cycling (6 m/s) speed. Hold a direction to move; release or cancel to hold the final point. Collapse, background, scene interruption, rotation, minimizing/closing a virtual window and PiP stop movement. Returning does not restart it. **Use System Location** is a separate confirmation action. Opening the panel pauses host Input Sync and requires manual resume.

Coordinate fields use the decimal keyboard with separate 44-point **±** controls and a **Done** keyboard action. The pair field accepts latitude then longitude, separated by a comma, semicolon or whitespace, using decimal points. An invalid pair blocks confirmation even if the separate fields still contain a previously valid point.

Movement publishes a small atomic snapshot at most once per second; there is no polling while idle. Local Darwin notifications refresh active accounts. A per-app file lock permits only one movement controller, and a settings revision prevents old movement from overwriting another account's newer selection. Only a selection or stop writes the durable app settings. Each tick uses monotonic elapsed time capped at 1.5 seconds, preventing a large jump after a delayed timer. A crashed/suspended controller's last point is retained but its speed becomes zero after 2.5 seconds. Host settings saves preserve current location preferences.

## Runtime contract

The first version supports the standard `CLLocationManager` delegate interface: `requestLocation`, `startUpdatingLocation`/`stopUpdatingLocation`, significant-change start/stop, and the `location` property. Managers created after installation have a retained proxy with weak references to the manager and the original delegate. Other delegate events are forwarded. Instances that predate installation retain their original behavior.

Authorization requests, status, precision authorization and system Location Services are not spoofed. A request waits while permission is undetermined and produces no coordinate. Denied/restricted permission or disabled services returns the normal denied error to the delegate; the location property is nil. The guest must request location access as it normally would. No permission descriptions or entitlements are inserted into guest bundles.

While enabled, the covered requests do not start real sensor updates. Authorized one-shot requests asynchronously publish the current location on the manager's creation run loop. Continuous subscriptions receive live changes and an idle one-second timer when no positive distance filter applies; duplicate identical events within a tick are suppressed. Stop cancels pending deliveries and the timer. A positive distance filter is measured from the last delivered sample; significant-change subscriptions use a 500 m threshold. These subscriptions have no idle periodic traffic. Changing the distance filter refreshes this policy. Significant-change monitoring does not arrange OS wakeups or background execution.

Samples have a fresh timestamp, 5 m horizontal accuracy, current movement speed/course, and unknown altitude accuracy. Stationary samples report zero speed and unknown course. They are marked as software-simulated through `CLLocationSourceInformation`. The last-location property returns the same delivered sample while authorized. The module does not override `CLLocation.coordinate` or constructors: independently created locations such as map destinations keep their original values. It is not an anti-detection feature.

This version does not cover WebKit's separate-process geolocation, newer Swift async location APIs (`CLLocationUpdate`), region/beacon monitoring, visit events, heading, IP-based location or background wakeups. Those retain system behavior. This is a compatibility/testing option, not a guarantee that every source of location in an app is replaced.

## Validation

The simulator suite exercises the production hook against a manager double to control authorization without touching system permissions. It checks saved-setting validation, opt-in gating, asynchronous one-shot delivery, unchanged ordinary CLLocation objects, permission changes, distance filtering, timer cancellation, delegate replacement, weak lifetimes, legacy callbacks, multiple managers and suppression of covered late system samples. A separate test uses a real CLLocationManager subclass with only authorization controlled, checking initialization, delegate storage and one-shot delivery. The iPhone/iPad UI suite runs the production picker, checks cancellation, zero/negative coordinates, validation and saved selections, and exports screenshots. Full compilation and existing window/input tests run in CI.

Device acceptance must additionally verify real Core Location behavior on an iPhone and iPad in ordinary, virtual and native launches; both permission choices; one and multiple accounts; settings upgrade/persistence; background/foreground; and the intended app's actual response. Simulator doubles do not establish private hosting behavior or game compatibility.
