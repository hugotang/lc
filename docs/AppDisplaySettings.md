# Per-app display settings (3.8.34)

Open an app's Settings → **Display & Layout**. Choices apply to all of that app's accounts in virtual multitasking windows. Close every running account of the app and reopen them after editing. Ordinary launches and native iPad windows do not use these options. TweakLoader injection must be enabled.

**Interface Mode (Experimental)** offers Automatic, iPhone and iPad. Automatic preserves system behavior. The other choices override `UIDevice.userInterfaceIdiom` and `UITraitCollection.userInterfaceIdiom` inside the isolated guest process, installed before the guest executable and its initializers load. This covers an app's cached device-type branches and existing as well as new trait collections. It is not a hardware emulator: the actual scale, safe areas, size classes, model and OS remain system values. An app must include suitable code and resources; UIKit or app-specific resource selection that does not consult these getters can retain the original layout. Verify the intended game's menus, dialogs, keyboard and ads on device. No `UIDeviceFamily` or guest executable is rewritten.

**Aspect Ratio** offers Fill Window, 9:16, 16:9, 3:4, 4:3 and Custom. Custom accepts two numbers from 1 to 10000, including decimals, with a quotient between 1:10 and 10:1. Canceling the custom editor leaves the saved setting intact. Fill Window is the default and removes the saved ratio.

A fixed ratio constrains the actual guest content view, fitting and centering it in the space available after any non-overlay window bar. The grid retains its slots and dividers; extra space is letterboxed. The chosen width:height does not swap when the device rotates. This is not an orientation lock: UIKit still receives the host's scene orientation. The dimensions in points may change with resizing or rotation while keeping the chosen ratio. Content scale applies once after fitting. Host controls and letterbox margins are outside the guest's touch surface, and Input Sync continues to map coordinates using the guest window's actual bounds.

Selecting a fixed ratio also enables the existing window-screen compatibility path for that launch, including its secondary-window and web-ad fitting. The **Use Window Size as Screen Size** switch shows on and is disabled while a ratio is selected; the user's independent screen-size preference is retained and applies again after selecting Fill Window. Host and guest use a captured launch-settings dictionary so changing an app preference during startup cannot split their geometry choices.

Workspace snapshots keep their existing format. Restoring uses each app's current display settings along with the workspace's saved grid, reservations and content scales. A running account is not silently resized into a new mode when its settings are edited. PiP remains controlled by iPadOS while the guest is temporarily hosted there; returning to its grid slot reapplies the fitted content area.

For Monster Strike, begin with Automatic + 9:16 and close/relaunch all accounts before comparing portrait launch → landscape and landscape launch → portrait. A stable aspect ratio addresses differing startup shapes, but does not establish a fix for the game's retained internal canvas. Test iPhone mode separately to distinguish the device-type branch from geometry. The existing Copy Window Geometry diagnostic includes the requested mode/ratio and guest device/trait idioms. Device acceptance is still pending; see [the manual checks](../Tests/MultitaskManualChecks.md).
