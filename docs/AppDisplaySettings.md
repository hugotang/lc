# Per-app display settings (3.8.38)

Open an app's Settings → **Display & Layout**. The ratio applies to all of that app's accounts in virtual multitasking windows, including when only one app window is open. Close every running account of the app and reopen them after editing. Ordinary launches and native iPad windows do not apply the ratio. TweakLoader injection must be enabled.

Version 3.8.35 removed **Interface Mode (Experimental)** and its process-wide device/trait idiom overrides. The app continues to use the system's device and trait behavior in 3.8.38, equivalent to the former Automatic choice. Saved `LCAppInterfaceMode` values from 3.8.34 are ignored; existing ratios and the independent screen-size compatibility preference survive the upgrade. No `UIDeviceFamily` or guest executable is rewritten.

**Aspect Ratio** offers Fill Window, 9:16, 16:9, 3:4, 4:3 and Custom. Custom accepts two numbers from 1 to 10000, including decimals, with a quotient between 1:10 and 10:1. Canceling the custom editor leaves the saved setting intact. Fill Window is the default and removes the saved ratio.

A fixed ratio constrains the actual guest content view, fitting and centering it in the space available after any non-overlay window bar. The grid retains its slots and dividers; extra space is letterboxed. The chosen width:height does not swap when the device rotates. This is not an orientation lock: UIKit still receives the host's scene orientation. The dimensions in points may change with resizing or rotation while keeping the chosen ratio. Content scale applies once after fitting. Host controls and letterbox margins are outside the guest's touch surface, and Input Sync continues to map coordinates using the guest window's actual bounds.

Selecting a fixed ratio also enables the existing window-screen compatibility path for that launch, including its secondary-window and web-ad fitting. In 3.8.38, **Display & Layout** shows a localized, noninteractive automatic compatibility status while any valid fixed ratio (preset or Custom) is selected. No compatibility switch is shown in that state.

With **Fill Window** selected, expand **Advanced** in **Display & Layout** to find **Use Window Size as Screen Size** and its existing explanation. This switch no longer appears on the main app settings page. It edits only the user's independent screen-size preference and remains unavailable when TweakLoader injection is disabled. Selecting a fixed ratio, viewing its automatic status or returning to Fill Window never changes that saved preference; the previous switch value applies again with Fill Window. This is a UI change only: host and guest still use a captured launch-settings dictionary so changing an app preference during startup cannot split their geometry choices.

Workspace snapshots keep their existing format. Restoring uses each app's current ratio along with the workspace's saved grid, reservations and content scales. A running account is not silently resized when its preference is edited. PiP remains controlled by iPadOS while the guest is temporarily hosted there; returning to its grid slot reapplies the fitted content area.

Input Sync still requires compatible actual content proportions, visible non-overlapping windows of the same app and ready input connections. Geometry changes invalidate the active session as before. The retired Interface Mode preference no longer affects eligibility; users must still align the app screens before starting sync.

For Monster Strike, begin with 9:16 and close/relaunch all accounts before comparing portrait launch → landscape and landscape launch → portrait. A stable aspect ratio addresses differing startup shapes, but does not establish a fix for the game's retained internal canvas. Copy Window Geometry includes the requested ratio and the guest's actual device/trait idioms. Device acceptance is still pending; see [the manual checks](../Tests/MultitaskManualChecks.md).

For **Puzzle & Dragons 23.6.0**, the user's corrected report on 2026-11-05 is that **Automatic + Custom 11:16 in virtual multitasking on 3.8.34** displays correctly on an iPad in landscape. **Forced iPad still overflows at the fixed ratio.** Screen-size compatibility was already enabled before the ratio change. The previous iPad + 11:16 success claim was incorrect. In 3.8.38, select Custom 11:16; the former Automatic behavior is always used. IDA inspection found portrait-only declarations and native layout calculations based on screen aspect and portrait-ordered dimensions; that explains a possible benefit of fixed geometry but does not establish the cause of the forced-mode failure. An exact required ratio and full gameplay/touch/advertising acceptance have not been established. The upgrade still needs device confirmation. See [PuzzleDragonsWindowSizing.md](PuzzleDragonsWindowSizing.md).

Fixed ratios remain scoped to virtual multitasking because that path controls the guest content area, letterboxing and touch surface together. Extending ordinary launches or native windows would require a separate design for system-owned geometry, rotation, keyboards and secondary windows, plus device validation. A single virtual window provides the current option for running one app at a fixed ratio.

## 3.8.38 display UI checks

- Confirm the main settings page contains **Display & Layout** but no standalone **Use Window Size as Screen Size** switch. In Fill Window, expand **Advanced** and check the existing switch title and description.
- Repeat with the independent preference both off and on: select each fixed preset and save a valid Custom ratio, confirm only the automatic compatibility status is shown, then return to Fill Window and verify the original switch value. Cancel a custom edit and confirm neither saved setting changes. Reopen settings and relaunch accounts to check persistence and existing compatibility behavior.
- Disable TweakLoader injection and confirm the aspect-ratio picker and the Advanced switch are unavailable. The automatic status must remain noninteractive when a fixed ratio is saved.
- Check localized labels and VoiceOver: the automatic status is text, and Advanced can be expanded to reach the switch. Stable accessibility identifiers are `displaySettings.open`, `displaySettings.aspectRatio`, `displaySettings.compatibilityAutomatic`, `displaySettings.advanced` and `displaySettings.useWindowScreenSize`. The new status and disclosure labels use `lc.appSettings.displaySettings.compatibilityAutomatic` and `lc.appSettings.displaySettings.advanced`.
