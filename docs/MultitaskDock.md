# Dock accounts and fullscreen controls

Starting in 3.8.15, each virtual-window Dock account has a number assigned in its app's container order. That number stays with the container when windows close, relaunch or swap grid positions. New containers receive the next number; removing a container does not renumber the others. The registry stores only container identifiers in shared preferences. It does not read or modify game files.

The optional caption uses the existing container name. A hand badge identifies the current Input Sync source, and VoiceOver also identifies selected followers. Input Sync's existing window-position labels still describe the current participant order; Dock numbers describe persistent account identity. Hidden app names, captions, icons and account numbers follow the app list's unlock state.

Use the Dock's ellipsis menu for Window Layout, Input Sync, Performance and Workspaces. Long-pressing the collapsed Dock opens the same menu. Long-press an account for its window actions, scale, PiP, sync role and Close. Copy PID is under Diagnostics. Account buttons retain a minimum 44 × 44 pt target and scroll when they exceed the available height. A very short host uses an account menu.

Drag the top handle to move the Dock or cross to the other edge. Hide Dock to Edge is available in the menu. The 3.8.17 outward gesture is retained: a swipe below the handle hides Dock as soon as horizontal travel reaches 16 pt with a clear outward direction, before lifting the finger. It waits through ambiguous initial jitter; a clear vertical or inward gesture cannot hide later in the same gesture. Handle drags, taps and long-press menus remain available; short outward drifts do not hide Dock. The recognizer claims a clear outward drag at 3 pt and cancels the pressed control, while still requiring 16 pt to hide. Native primary-action menu gestures inside Dock wait for the swipe recognizer to fail before opening, so a drag cannot open the menu and lose its contact; a normal tap opens it on release. Account long presses and scroll gestures continue alongside the recognizer.

Tap the edge tab or swipe inward near it to reveal Dock. In 3.8.19 the arrow keeps its original 16 × 44 pt artwork and placement, while its native host touch target grows from 44 × 44 to 64 × 132 pt, clipped to the host window. This includes 44 pt above/below the old target and 20 pt farther inward. Hide Collapsed Dock hides only the artwork. Near-arrow swipes reveal after 16 pt of inward horizontal travel measured from touch-down, allowing slight initial diagonal movement without losing the gesture to UIKit's pan slop. Stationary taps and VoiceOver activation remain available; recognised short, vertical or outward drags do not also activate the tap. This local patch receives touches instead of the game, including taps and vertical drags; space outside it continues to receive game input.

In 3.8.20 the host control keeps a cached 1 × 1 fully transparent image in its layer in both arrow modes. Hiding the arrow previously left the host layer with no image or visible children. The user's 3.8.19 device comparison found that inward reveal worked after Minimize All Windows and with the arrow visible, but failed over four visible Monster Strike accounts when Hide Collapsed Dock was enabled. That points to delivery/rendering rather than the travel threshold. [A separate iOS 26/27 investigation](https://github.com/TelegramMessenger/Telegram-iOS/blob/fb0e62ba8a147f0821da6aa63c09da7d79a10111/docs/ios27-windows-and-touches.md#a-layer-that-renders-nothing-receives-no-touches) reports that an entirely empty render layer can lose real touch delivery despite successful UIView hit testing, and that transparent image contents retain delivery. This supplies a public-API fix to test on the affected device, without an undocumented opacity threshold. The image stays invisible and uses the existing local target, with no new window, changed gesture thresholds or periodic work. The exact private-scene cause is still unproven until the device retest.

The window gesture also restores the original ability to reveal from either edge, within 44 pt at any height, after 30 pt of inward horizontal travel. It determines direction from the touch's starting edge, waits through small initial jitter, and rejects deliberate vertical/outward motion. It accepts one finger, leaves guest touches undelayed and uncancelled, and can recognize alongside guest gestures. No full-height overlay is added. Repeated workspace refreshes preserve both recognizers when frame/side remain unchanged; hide cancels the local contact and removes the owned window gesture, host migration removes the old window gesture, and frame/side changes cancel pending drags.

Portrait and landscape placement are saved independently as an edge and a normalized height. Resizing clamps placement to the current host safe area. Settings → Multitasking → Dock → Reset Dock Positions clears both placements and immediately reveals a hidden Dock, leaving account numbers and Input Sync settings intact. VoiceOver provides corner placement actions and tab activation, and Reduce Motion disables movement springs.

**Overlay Fullscreen Controls** is an optional setting, off by default, inspired by [LiveContainer PR #1490](https://github.com/LiveContainer/LiveContainer/pull/1490). It applies only to maximized virtual windows. The bar overlays the guest at the selected top/bottom safe-area edge. Expanding or collapsing Dock changes chrome visibility without changing guest bounds or safe areas, rebuilding guest constraints or submitting a guest frame update. The visible controls cover that strip of game content and receive their own input.

Returning to floating/grid layout or disabling overlay restores the existing reserved-row behavior. Actual layout/scale changes retain Input Sync's interruption handling. Foreground interruption still requires manual Resume. Keyboard avoidance, PiP and terminated-window controls retain their existing behavior.

The Foundation suite covers stable identifiers, placement, reset, geometry and overflow. UIKit tests exercise production chrome layout, hit testing and reveal direction/distance, jitter, cancellation and multiple fingers. The image test checks a nonempty 1 × 1 CGImage with zero rendered alpha, retained through both sides, arrow toggles and hide/show. `run-dock-gesture-ui-tests.sh` drives real simulator touches through production gestures with SwiftUI accounts, menus and scrolling. Four ordinary guest-like views carry competing pans; reveal cases cover arrow on/off, 22–24 pt short/diagonal/quick swipes around the tab, opposite-edge recovery, edge starts, repeated refresh/hide and guest input. Two additional cases use four WKWebViews with out-of-process rendered content, live JavaScript guest-touch reporting, guest minimize/restore and repeated arrow toggles. WebKit's input transport differs from the game's private scene hosting, so these tests cannot prove Monster Strike recovery. Earlier 3.8.18/3.8.19 simulator results did not settle the device bug. Real device checks are in [MultitaskManualChecks.md](../Tests/MultitaskManualChecks.md).
