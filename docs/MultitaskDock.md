# Dock accounts and fullscreen controls

Starting in 3.8.15, each virtual-window Dock account has a number assigned in its app's container order. That number stays with the container when windows close, relaunch or swap grid positions. New containers receive the next number; removing a container does not renumber the others. The registry stores only container identifiers in shared preferences. It does not read or modify game files.

The optional caption uses the existing container name. A hand badge identifies the current Input Sync source, and VoiceOver also identifies selected followers. Input Sync's existing window-position labels still describe the current participant order; Dock numbers describe persistent account identity. Hidden app names, captions, icons and account numbers follow the app list's unlock state.

Use the Dock's ellipsis menu for Window Layout, Input Sync, Performance and Workspaces. Long-pressing the collapsed Dock opens the same menu. Long-press an account for its window actions, scale, PiP, sync role and Close. Copy PID is under Diagnostics. Account buttons retain a minimum 44 × 44 pt target and scroll when they exceed the available height. A very short host uses an account menu.

In 3.8.18, drag the whole Dock to move it, as before the separate three-line handle was added. The handle and separate native hide recognizer have been removed. The SwiftUI drag follows the finger after 5 pt of movement. Release an outward, mainly horizontal drag to hide Dock; it needs no additional 16 pt distance or throwing speed. Release a vertical drag to change height, or drag inward past the screen center to switch edges. When the account list overflows, vertical account scrolling stays within the list; the Dock background remains draggable. Taps and account/collapsed long-press menus remain available. Hide Dock to Edge is also available in the menu.

Tap the edge tab or drag it inward to reveal Dock. The tab remains a separate native 44 × 44 pt control entirely inside the host window. Hide Collapsed Dock hides its arrow; the original touch area remains active. An inward swipe from the hidden edge also reveals Dock and can recognize alongside game gestures. Portrait and landscape placement are saved independently as an edge and a normalized height. Resizing clamps placement to the current host safe area and cancels an unfinished drag. Settings → Multitasking → Dock → Reset Dock Positions clears both placements and immediately reveals a hidden Dock, leaving account numbers and Input Sync settings intact. VoiceOver provides corner placement actions and tab activation, and Reduce Motion disables movement springs.

**Overlay Fullscreen Controls** is an optional setting, off by default, inspired by [LiveContainer PR #1490](https://github.com/LiveContainer/LiveContainer/pull/1490). It applies only to maximized virtual windows. The bar overlays the guest at the selected top/bottom safe-area edge. Expanding or collapsing Dock changes chrome visibility without changing guest bounds or safe areas, rebuilding guest constraints or submitting a guest frame update. The visible controls cover that strip of game content and receive their own input.

Returning to floating/grid layout or disabling overlay restores the existing reserved-row behavior. Actual layout/scale changes retain Input Sync's interruption handling. Foreground interruption still requires manual Resume. Keyboard avoidance, PiP and terminated-window controls retain their existing behavior.

The Foundation suite covers stable identifiers, placement, reset, geometry, overflow and whole-Dock release decisions. UIKit tests exercise the retained edge reveal control and production chrome layout. `run-dock-gesture-ui-tests.sh` drives simulator touches through the same production SwiftUI drag modifier and release policy used by Dock, with pressed account buttons, context menus, a Menu, vertical ScrollView, both hosting-view edges and a collapsed Dock. Real device checks for game layout, touch forwarding, keyboard, rotation and PiP are in [MultitaskManualChecks.md](../Tests/MultitaskManualChecks.md); simulator tests do not establish private guest-scene compatibility.
