# Dock accounts and fullscreen controls

Starting in 3.8.15, each virtual-window Dock account has a number assigned in its app's container order. That number stays with the container when windows close, relaunch or swap grid positions. New containers receive the next number; removing a container does not renumber the others. The registry stores only container identifiers in shared preferences. It does not read or modify game files.

The optional caption uses the existing container name. A hand badge identifies the current Input Sync source, and VoiceOver also identifies selected followers. Input Sync's existing window-position labels still describe the current participant order; Dock numbers describe persistent account identity. Hidden app names, captions, icons and account numbers follow the app list's unlock state.

Use the Dock's ellipsis menu for Window Layout, Input Sync, Performance and Workspaces. Long-pressing the collapsed Dock opens the same menu. Long-press an account for its window actions, scale, PiP, sync role and Close. Copy PID is under Diagnostics. Account buttons retain a minimum 44 × 44 pt target and scroll when they exceed the available height. A very short host uses an account menu.

Drag the top handle to move the Dock or cross to the other edge. Hide Dock to Edge is available in the menu. In 3.8.17, an outward swipe below the handle hides Dock as soon as horizontal travel reaches 16 pt with a clear outward direction, before lifting the finger. It waits through ambiguous initial jitter; a clear vertical or inward gesture cannot hide later in the same gesture. Handle drags, taps and long-press menus remain available; short outward drifts do not hide Dock. The recognizer claims a clear outward drag at 3 pt and cancels the pressed control, while still requiring 16 pt to hide. Native primary-action menu gestures inside Dock wait for the swipe recognizer to fail before opening, so a drag cannot open the menu and lose its contact; a normal tap opens it on release. Account long presses and scroll gestures continue alongside the recognizer. Tap the edge tab or drag it inward to reveal Dock. The tab is a separate native 44 × 44 pt control entirely inside the host window. Hide Collapsed Dock hides its arrow; the original touch area remains active. An inward swipe from the hidden edge also reveals Dock and can recognize alongside game gestures. Portrait and landscape placement are saved independently as an edge and a normalized height. Resizing clamps placement to the current host safe area. Settings → Multitasking → Dock → Reset Dock Positions clears both placements and immediately reveals a hidden Dock, leaving account numbers and Input Sync settings intact. VoiceOver provides corner placement actions and tab activation, and Reduce Motion disables movement springs.

**Overlay Fullscreen Controls** is an optional setting, off by default, inspired by [LiveContainer PR #1490](https://github.com/LiveContainer/LiveContainer/pull/1490). It applies only to maximized virtual windows. The bar overlays the guest at the selected top/bottom safe-area edge. Expanding or collapsing Dock changes chrome visibility without changing guest bounds or safe areas, rebuilding guest constraints or submitting a guest frame update. The visible controls cover that strip of game content and receive their own input.

Returning to floating/grid layout or disabling overlay restores the existing reserved-row behavior. Actual layout/scale changes retain Input Sync's interruption handling. Foreground interruption still requires manual Resume. Keyboard avoidance, PiP and terminated-window controls retain their existing behavior.

The Foundation suite covers stable identifiers, placement, reset, geometry and overflow. UIKit tests exercise the production chrome layout with repeated visibility/edge changes, safe areas, resized hosts, normal/grid transitions and hit testing. `run-dock-gesture-ui-tests.sh` also drives real simulator touches through the production hide recognizer and a SwiftUI fixture with pressed account buttons, context menus, a Menu and a vertical ScrollView. It checks short outward swipes on both edges at 56/80 pt widths, hiding during an active touch without an account tap, scrolling, handle movement, taps and long presses. Real device checks for game layout, touch forwarding, keyboard, rotation and PiP are in [MultitaskManualChecks.md](../Tests/MultitaskManualChecks.md); simulator tests do not establish private guest-scene compatibility.
