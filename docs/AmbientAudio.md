# Ambient audio compatibility

Version 3.8.31 adds a saved, opt-in **Ambient Audio (Experimental)** switch in each app's settings. It is off by default and applies to all of that app's injected virtual LiveProcess accounts after they are closed and relaunched. Disable it and relaunch those accounts to restore their original audio-session setters. The host, native-window guests, ordinary single-process launches and guests with tweak injection disabled keep their existing audio behavior.

The user reported that Japanese Monster Strike has background music with one account, but no music after four accounts start. Effects still play. Muting three accounts through the game's own sound settings did not restore the fourth account's music. A zero game volume does not deactivate its audio session or guarantee a mixable category.

This switch converts playback-only Ambient, Solo Ambient and Playback category requests to **Ambient**, default mode, default sharing policy and no explicit options. Ambient mixes with other audio and honours the device's silent switch. Playback-specific modes, ducking and route-sharing options are omitted for those converted categories. Record, Play and Record, MultiRoute and unknown categories keep their requested values. All four Objective-C category setters, a later playback mode setter and the legacy `AudioSessionSetProperty('acat', ...)` playback categories are covered. A thread-local guard allows original setters to forward to one another without re-entering the conversion and is restored on exceptions. Errors still return to the caller; the switch does not claim success when the original setter fails.

Hooks install before guest initializers and before the existing dyld image hiding. The initial setup configures the session without activating it. The guest keeps control of activation, deactivation and real interruption handling. The implementation adds no timer, audio replay, forced playback, microphone-category conversion or interruption suppression. It does not change the system volume or the game's BGM/effect preferences. Use those preferences to mute the other three accounts; a LiveContainer per-account output-mute controller is not part of this first experiment.

## What the executable established

Read-only IDA analysis used the same Monster Strike 33.0.0 executable identified in [MonsterStrikeWindowSizing.md](MonsterStrikeWindowSizing.md). Its own startup at `0x1006AF5FC` and delayed interruption recovery at `0x1004F7A94` already request `AVAudioSessionCategoryAmbient`. The legacy OpenAL recovery at `0x100B1F11C` writes `0x616D6269` (`'ambi'`), which is also Ambient; **it is not Solo Ambient**. An initial interpretation of that constant as exclusive was corrected against `AudioSession.h` before implementation.

The game contains OpenAL effect/stream-player types and handles real interruptions by pausing audio and scheduling recovery. Embedded advertising SDK paths also request Solo Ambient or Playback categories. These findings initially justified a category compatibility experiment; the device result below shows that category conversion alone does not resolve this report.

## Device result and native other-audio detection

On 2026-10-30 the user tested 3.8.31 and reported that effects still played without BGM. Read-only USB inspection confirmed version 3.8.31 and `LCForceAmbientAudio = true` for the Japanese game inside LiveContainer. Starting the second account immediately stopped the first account's music; closing the other accounts restored the remaining account's music without restarting it. The user reproduced both transitions during a bounded audio-log capture.

Retained task-scoped logs show both guest sessions as `AmbientSound/Default`, `Mixable`, with unmuted output. A host Playback session was also active. The capture retained the last 1,200 matching events, so heavy routine audio-query chatter discarded earlier lifecycle events. App-initiated deactivations in the retained tail cannot be assigned specifically to BGM or an exact user action. These logs do not establish exclusive category contention as the cause.

Read-only IDA found the game's native `isOtherAudioPlaying` wrapper at `0x10174C068`. Its audio-manager update at `0x10009EA18` uses that value while the application is active (`0x1008D1F0C`) to reversibly disable and pause eligible stream sources. When the value becomes false, it enables and resumes those sources. The enable flag is written by `0x1000133AC` and checked before OpenAL playback at `0x100478F48`. This branch closely matches second-account stop and last-account recovery. Ambient mixing does not promise a false `isOtherAudioPlaying` result, even when the other game has zero volume. The matched branch is actionable evidence; a runtime trace has not directly sampled that Boolean or proved that it is the sole cause.

## Keep Background Music (3.8.32)

The separately saved **Keep Background Music (Experimental)** app option (`LCKeepBackgroundAudio`) defaults off and requires closing/relaunching all accounts. It installs only for injected virtual LiveProcess guests and is independent of Ambient Audio. For playback-only categories, direct calls to `isOtherAudioPlaying` from the selected guest executable return false after calling the original query. Unknown callers, system/framework code and separately loaded SDKs retain the original result. Recording, Play and Record, MultiRoute and unknown categories also retain the original result.

An image callback registers before the existing dyld path hiding and identifies the exact guest executable before its initializers. Queries compare loaded image identity rather than a hidden path. Failed image identification keeps the real result. Statically linked ad/SDK code belongs to the same executable and cannot be separated by this boundary; it can also see the adjusted result. Only one install, image-identification and first-adjusted-query message are emitted; no account name, path or touch data is included. There is no polling timer, engine replay, native game offset patch, automatic activation or interruption-notification hook. The PiP manager's host session is unchanged.

This option can make game music mix with external music or in-process ads, because the query does not identify which process owns the other audio. Use in-game preferences to mute the other accounts. It does not enforce one audible account or provide a LiveContainer output-mute controller. Calls, Siri, recording and real interruptions remain the game's responsibility. Turning the option off and relaunching restores original detection without changing saves or resources.

On 2026-10-30 the user reported that Monster Strike launched and BGM worked after switching to **LiveContainer+SideStore 3.8.32**, then confirmed that all previously saved workspaces reappeared. The initial game-termination and missing-workspace report followed installation of the ordinary package. The user installs through iloader by overwriting the existing app. Switching back to the SideStore package resolved that report without a runtime rollback or data recovery. Use the SideStore package for this user's subsequent updates; this result does not establish that ordinary packages fail in other installations or prove the exact App Group/JITLess mechanism.

This records successful launch, reported BGM recovery and workspace recovery on the affected iPad. The account count and audio-toggle combination were not separately reported for the successful run. Stage transitions, ads, external music, real interruptions and the complete physical audio procedure below remain unreported; this result does not pass that entire matrix.

## Validation and device procedure

Controlled simulator tests exercise the Ambient launch gate, all playback setters with nested original forwarding, recording/unknown-category preservation, playback mode normalization, original errors/exceptions, and legacy category conversion/data forwarding. Background-music tests additionally use a separate controlled session class to verify the saved launch gate, guest-image playback queries, real framework-originated invocation, inherited-method isolation, unknown/unrelated images, recording categories and original exceptions. They do not run Monster Strike or reproduce device audio arbitration.

On the affected iPad, keep the device unmuted, set BGM/effects to zero in three accounts and leave the fourth audible. First record the option-off baseline. Close all accounts, enable Ambient Audio in Monster Strike's LiveContainer app settings, then restore the same four-account workspace. Check BGM while the later accounts finish loading, new effects, a stage transition, follower/source actions and rotation. Test an ad opening/closing and confirm the chosen game still owns its expected audio afterwards. Check another music app separately to confirm it is not paused by playback-only game requests. Repeat with the option off after relaunch. A call, Siri, microphone recording or a real system interruption can still pause the game's audio; this option does not bypass those events. Record outcomes separately from the simulator results.

For 3.8.32, close all accounts, enable **Keep Background Music**, and first test with Ambient Audio off to isolate detection from category conversion. Open the audible account, start the second muted account, then restore all four. Check music through launch/loading, stage transitions, effects and ad open/close. Rotate, use Input Sync and enter/return from background or PiP. Repeat with Ambient also enabled if an SDK's category still interferes, and record those results separately. Verify another music app may mix rather than forcing the game to stop, then verify normal real-interruption recovery. Disable Keep Background Music, relaunch and confirm the original two-account stop/last-account recovery returns. Device acceptance must be recorded separately from controlled tests.
