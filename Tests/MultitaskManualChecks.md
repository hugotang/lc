# Device checks for multitasking changes

The standalone tests cover geometry, ordering, workspace serialization, localization selection and symbol-cache validation. AVKit transitions and private guest-scene APIs also need these checks on an iPhone and iPad; a successful archive does not exercise them.

- Terminate a maximized app with the Dock collapsed, with the window bar at the top and bottom. Check that close, minimize and restore remain usable, then rotate and maximize again. Repeat with grid bars hidden and with “Skip Terminated Screen” enabled.
- With automatic tiling both on and off, open and dismiss a docked keyboard in windows near the bottom of the screen. Verify text remains visible and the original geometry and custom grid proportions return. Repeat after rotation, minimize/restore, changing the keyboard preference, and with a floating or hardware keyboard.
- With the default portrait reserved areas, in landscape left/right and portrait, tile 1, 2, 3, 4 and 6 apps. Verify the bottom row draws to the screen edge without a full-width host-colored strip, while app controls still avoid the home indicator and top/side system exclusions remain. Repeat with 50%, 100% and 200% content scales, grid bars visible/hidden and at the top/bottom, a terminated window, keyboard show/hide, and a restored workspace. Check iOS 16/17's legacy presenter as well as iOS 18+ scene hosting; floating-window placement must be unchanged.
- Select Landscape Layout → Single Row in Settings and the Dock's layout menu. With 1, 2, 3, 4 and 6 windows, rotate between portrait and both landscape directions: portrait keeps the automatic grid and landscape uses one full-height row, preserving app order. Adjust column widths, swap windows and undo, then switch to Automatic Grid and back; each grid shape keeps its proportions. Repeat with a manually arranged grid and automatic tiling off, and change the selection during divider/swap editing and keyboard show/hide. Changing the preference alone must not tile floating windows. Save a workspace, change the preference, and restore through Settings and the Home Screen shortcut; the saved preference and each shape's proportions must return. Restore an older workspace to confirm it uses Automatic Grid.
- Test all four Portrait Reserved Areas combinations from Settings and the Dock. On a portrait grid, disabling Reserve Top Area extends content behind the status bar/Dynamic Island; enabling Reserve Bottom Area stops the grid above the home indicator. Verify supporting apps keep buttons clear at 50%, 100% and 200% scale, with grid bars shown/hidden, and that both landscape directions retain their existing exclusions. Rotate a manually arranged grid with automatic tiling off, including after returning to the default options; floating/maximized windows must keep their placement. Change options during divider/swap editing and keyboard show/hide; app order and saved proportions must survive, and near-square iPad windows must not become a landscape single row just because of the reserved space. Save two workspaces with different top/bottom choices, restore each by its shortcut, and check the saved values in Manage Workspaces. Restoring an older save must reserve the top and extend the bottom.
- Enter PiP with a software keyboard open. Check that the PiP window uses the full screen and the keyboard remains dismissed after returning. Repeat with a hardware keyboard to check retained focus. Switch PiP between two apps quickly, stop during startup, close the guest, and exercise an AVKit startup failure; no window should remain hidden or frozen.
- Upgrade with an existing single workspace. Verify it appears once as Original Workspace, keeps its apps and landscape preference, and does not duplicate after restarting or changing the language. Save a second named workspace with different apps, containers, order, scales and divider proportions; restore each independently from Settings and the Dock. Unrelated running windows remain open.
- In Manage Workspaces, rename, update and delete entries. Cancel each prompt first; no save may change. Names must be nonempty, at most 80 characters and distinct ignoring case. Update one entry without changing the others; restart and check order and content. Delete the last entry and restart: the old migrated save must not reappear. Verify the list/detail pages, dismissal and actions on both iPhone and iPad.
- In a saved workspace's detail page, edit both reserved areas and the landscape picker with no guest running, then with a different set of guests open. Verify immediate persistence without a confirmation or changes to the live layout; restarting and restoring the dedicated shortcut must use those options while retaining the saved apps, containers, order, scales, divider proportions and UUID. Another workspace, the list order and the legacy link's latest workspace must stay unchanged. After a separate reader renames or replaces a workspace, edit one preference from the open detail page and verify the latest name/windows and the other preferences are preserved. A storage failure must show an error and roll back the control; a deleted record must not reappear.
- Swipe a saved row left for Rename/Delete and right for Restore. A full swipe must not execute an action. Cancel deletion and confirm the row remains visible; confirm deletion and check the matching detail page closes. Test the same actions with VoiceOver and the detail toolbar. Search by partial name and case/diacritic variants, clear an empty result, and create a new workspace or duplicate while searching; the new detail page must open. Duplicate an 80-character/emoji name, edit its options, and verify the original save and link remain unchanged. Check transient success messages, restore progress, storage-error retry, large text and both phone/tablet orientations.
- Inspect saved window details for multiple containers of the same app, renamed containers, different scales, a removed app/container and hidden apps before/after unlocking the app list. Hidden names/icons/containers must remain concealed while locked. Expand the Home Screen shortcut instructions and the grid help in Settings; copying from Manage Workspaces must show a brief confirmation without another OK dialog. Verify the main Restore action and the separate Update with Current Windows action remain clear and usable.
- Restore from the list swipe, long-press menu, detail button and Settings/Dock shortcut menus. Successful restores must show the running workspace directly without an OK dialog; authentication cancellation must launch nothing, and partial/failed restores must still show their result. Verify the restoring indicator and disabled edit controls while authentication or app startup is pending.
- Restore when a saved app or container has been deleted, a saved window is terminated/minimized/in PiP, one app fails to launch, or an app has switched to classic mode. Check partial results, no duplicate windows and no launch into another container. Verify locked/hidden apps require authentication and canceling authentication launches nothing.
- Copy dedicated restore links for two workspaces from Settings and the Dock. In Shortcuts, use URL → Open URLs, then add each to the Home Screen with a name and icon. Cold and warm launches must restore the selected workspace even after another is saved, and renaming/updating must keep the same link. A deleted workspace's link must report unavailable without opening another save. Also check a legacy link without a selection restores the most recently saved/updated entry, and repeat through LiveContainer's Launch App action and an additional LC installation.
- Tap the restore shortcut repeatedly during startup and authentication. Verify one restore runs, existing windows are reused, successful shortcut restores need no confirmation, and missing apps/containers still report partial results. No saved workspace or native-window mode must produce an error without launching guests.
- Run a guest in normal mode and open each named restore shortcut. Accept the existing app-switch confirmation and verify the requested workspace is restored after returning to the host, even when it is not the latest save. Cancel and verify no later restore is queued; repeat with switching without asking enabled and with Keep Selected When Quit after terminating LC. A request left for more than two minutes must not restore on a later ordinary launch.
- Check that sources with positive IPA sizes show a localized size before downloading; missing/zero sizes remain omitted.

## Experimental input sync

- On an iPhone 17 Pro with iOS 27, open two containers of the same app, then repeat with four. From the Dock and Settings, choose a source, select only some followers, start, and tap simple controls at the center and near each edge. Only selected containers should receive one down/up pair per completed tap; the source must not receive a duplicate. Check native UIKit buttons, SwiftUI controls and the intended game separately. A forwarded count is not proof of the app action succeeding.
- Repeat in portrait and both landscape directions, at 50%, 100% and 200% content scale, with reserved areas and window bars enabled/disabled. Controls outside the guests (Dock, status button, grid dividers and window bars) must not be forwarded. A mismatching orientation/aspect ratio must pause or prevent start. Starting with overlapping, partly offscreen, minimized or PiP windows must be unavailable.
- In Taps Only mode, check slow/rapid taps and double taps, a drag that returns to its starting point, a long press, two fingers, keyboard entry and a hardware pointer. Only direct short single-finger taps are eligible. Confirm games see the down and up phases. If any selected app ignores replay, stop and record its version and the setup; do not describe that app as supported based only on the counter.
- Pause with a tap pending, restart immediately, and close/relaunch a follower. Rotate, resize, maximize, edit the grid, minimize, enter PiP, open the keyboard, lock the phone and leave the foreground. Input and queued work must stop; no old tap or delayed reply may reactivate the next session or leave a synthetic finger down. Touch a follower directly while a replay is pending and confirm its physical input still works after cancellation.
- Make a follower slow or unresponsive. The host must stop rather than accumulate or replay old input after recovery. Confirm that missing private APIs or an input connection show an unavailable state and do not crash the host. Check selecting/deselecting followers, changing the source, clearing the group, the persistent pause/resume and settings controls with the Dock hidden, VoiceOver and large text. Hidden app names/icons/container names must stay concealed until unlocked.
- Save and duplicate a workspace with a group, rename it and edit its reserved areas, then restore through the list and its Home Screen link. Source/follower roles must survive, but forwarding must stay paused until explicitly started. Restore an older workspace, or one with a missing/malformed/different-app group: its valid layout must survive without enabling sync. Check normal single-app launching and multitasking with no group for regressions, and compare idle CPU/thermal behavior with sync off, paused and active without touching the screen.
- Select Single Finger with two instances, then four. Test taps, double taps, slow/fast scrolling, reversals, sliders, a long drag returning to its starting position, a long press without movement (including a 30-second hold), and dragging/releasing outside the original window. Each follower should see one continuous contact, the initial hit view and an appropriate release/cancel; no edge control should be clicked just because coordinates were clamped. Check UIKit, SwiftUI and each intended game separately. The counter should increment once per completed gesture, never on every move.
- While holding/dragging in Single Finger, pause using a second finger on the host control, open settings, add a second finger inside the source, touch a follower, show/type with a keyboard, rotate/resize, change modes, close a follower, background/lock and disconnect. Every synthetic contact must cancel immediately. Resume quickly and ensure no queued move, release or delayed callback belongs to the new session. Make a follower slow during a drag and check bounded delay and cancellation after failure, including when release arrives while the queue is full.
- Drag the floating controls by their main button and gear; dragging must not toggle sync or open settings. Check left/right docking at top/middle/bottom, relaunch, portrait and both landscape directions, safe-area changes, compact mode, Dynamic Type, Reduce Motion and VoiceOver corner actions. Short taps always pause/resume; the separate gear always opens setup. Expanded paused controls and setup show the pause reason. Verify source/follower labels match the setup window numbers and do not consume touches, and hide them if they cover desired content.
- Switch the source among selected same-app windows and verify the remaining group survives; switch to another app and select a new group. Minimize/close a selected follower and remove unavailable selections from setup, then restore it and reselect. A hidden/missing source must explain how to restore or replace it.
- With no guests running, edit Sync Group from a saved workspace: select a source, followers and mode, Save, reopen, duplicate and restore via its dedicated shortcut. Repeat while a different live group is active; editing the save must not replace it. Back out of unsaved changes, clear and save, modify reserved areas afterwards, and edit from a stale reader after a rename/window replacement/deletion. Only the intended saved group should change; links, names, order, windows, scales and proportions remain correct, invalid edits report failure, and restoration stays paused. Older/unknown modes fall back to Taps Only.
- Compare idle and scrolling CPU/thermal behavior with sync off, Taps Only and Single Finger, at the same app screen/brightness and with two/four instances. Check that stationary holds and idle sessions produce no periodic input traffic and that dense moves coalesce without losing begin/end/cancel. Record device/app versions and measured behavior; automated tests do not measure latency, frame rate or heating.

## Two-finger input and performance monitoring

- In Two Fingers mode, test a slow/fast pinch and rotation, two-finger scrolling and two simultaneous buttons in two/four copies of the intended app. Hold a joystick with one finger while repeatedly tapping/releasing another control. The held finger must remain down; each receiving contact must preserve its identity and original hit view. Check both UIKit/SwiftUI and game controls, including views that reject multiple touches.
- Release both fingers together, release/reintroduce only one, and alternate which finger moves while the other stays still. Include rapid replacements and movement outside the original guest bounds. No contact boundary may disappear during coalescing, and finger A's move must not be lost when a newer frame moves only finger B.
- Add a third active finger, touch a follower directly, change source, remove a follower, rotate, resize, minimize, close a window, background, show the keyboard, and trigger a follower timeout during a two-finger hold. Both receiving fingers must cancel, later physical input must work, and immediate restart must reject old frames/replies. User input still goes to the source normally after pausing sync.
- Verify the pause panel identifies the actual interrupted/unresponsive window(s); remove one follower without closing its app and retain any other reported blockers. Use both a window title menu and its Dock menu to switch sources. Other same-app selected members remain, the old source becomes a follower if possible, and the group stays paused. Repeat after closing the old source and with a different-app source.
- Save/edit/duplicate a workspace in Two Fingers mode and restore it via its link. Mode and members return paused, without active contacts or measurement state. Older and unknown modes still fall back to Taps Only; layout/reserved-area settings and locked-app privacy remain unchanged.
- Run the monitoring lifecycle and comparison checks in [PerformanceTesting.md](../docs/PerformanceTesting.md). Record device results; the CPU/percentile math tests and successful iOS archive do not establish on-device overhead, GPU usage, input latency or power savings.
